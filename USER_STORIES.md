# Formulary — User stories

**Product:** [PRODUCT.md](./PRODUCT.md)


### Chief Data and Analytics Officer

- As the Chief Data Officer, I want candidates rejected at intake when their formula is incomplete, so that my pipeline holds specified use cases rather than aspirations.
- As the Chief Data Officer, I want the portfolio's quadrant balance visible against a target, so that I can show the committee we are not spending the entire envelope on cost reduction.
- As the Chief Data Officer, I want each candidate's booked benefit tracked after go-live, so that next year's envelope is argued from realised numbers.
- As the Chief Data Officer, I want to see the most common data-readiness failure reasons across rejected candidates, so that I can invest in the data asset that unblocks the most value.

### Business sponsor in claims, underwriting, or servicing

- As a claims sponsor, I want to state my need and have the formula guide me to a functionality and data type, so that I am not required to arrive with a solution I am not qualified to design.
- As an underwriting sponsor, I want to know before build whether the data I am counting on is permitted and how much of my book it actually covers, so that I do not launch a capability that works for a third of my portfolio.
- As a servicing sponsor, I want a small first release with a defined evidence target, so that I can prove the case without committing to a multi-year programme.
- As a sponsor, I want to see comparable use cases already delivered inside the company, so that I stop re-proposing something a neighbouring function has running.

### Data owner and steward

- As a data owner, I want to record a readiness verdict with reasons, so that a candidate is stopped on evidence rather than on my informal reluctance.
- As a data steward, I want each third-party and public data dependency to carry its permission basis and renewal date, so that expiry is visible before it becomes a compliance event.

### Conduct, actuarial, and model risk reviewer

- As a conduct officer, I want any candidate touching rating, renewal price, acceptance, or claims decisions routed to me before build, so that a proxy-discrimination problem is found at design time and not at rate filing.
- As a pricing actuary, I want to review the proposed feature set for factors that are proxies for protected characteristics, so that our rating structure remains defensible.
- As a model risk reviewer, I want every production model registered with owner, use cases, and data dependencies, so that I can evidence model inventory completeness in the own risk and solvency assessment.
- As a conduct officer, I want to withhold approval for a candidate whose benefit depends on differentiating renewal price by inferred price sensitivity, so that a prohibited practice never reaches build.

### Investment committee member and portfolio administrator

- As a committee member, I want a single quarterly view of committed spend, quadrant balance, booked benefit, and kills, so that funding decisions are comparable across candidates.
- As a committee member, I want cross-industry analogues shown with their transfer assumption stated, so that I can judge whether a manufacturing result really implies an insurance result.
- As a portfolio administrator, I want kill criteria and decision dates fixed at admission and enforced by the system, so that closing a use case is a policy outcome rather than a political fight.
